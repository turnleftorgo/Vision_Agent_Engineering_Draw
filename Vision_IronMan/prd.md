# Qwen 图像模块盲测工具 PRD

## 1. 产品概述

`qwen_module_blind_test.py` 是一个面向视觉模型评估的命令行工具。它将一张完整原图一次性提交给兼容 OpenAI API 的 Qwen 视觉语言模型，让模型直接识别图像中在视觉结构或语义上相对独立的内容模块，并输出每个模块的边界框和简短描述。

该工具的核心目的不是获得经过工程优化的最佳检测结果，而是建立一个受控、可复现的盲测基准，用来观察模型在没有传统视觉预处理和检测后处理帮助时的原生模块发现与定位能力。

## 2. 背景与问题

复杂图像可能包含多个相对独立的内容区域，例如工程图视图、注释区域、表格、标题栏或其他结构化模块。在完整检测系统中，切图、OCR、OpenCV 候选生成、NMS、框合并和多次模型请求都会影响最终结果，因此难以判断结果究竟来自模型自身能力，还是来自外围工程策略。

本工具通过固定以下条件隔离模型能力：

- 使用未经切片的完整图像；
- 只进行一次模型请求；
- 不使用 OCR 或传统视觉算法生成候选；
- 不做 NMS、边界框合并或语义补全；
- 不修复模型生成的非法 JSON；
- 只对合法结果做 schema 校验和坐标换算。

## 3. 产品目标

### 3.1 核心目标

1. 测量 Qwen VLM 对完整图像中独立内容模块的零样本发现能力。
2. 测量模型输出归一化边界框的定位能力。
3. 保存足够的原始数据，使单次测试结果可以审计和复查。
4. 严格区分模型原始输出、解析结果、有效检测和无效对象。
5. 生成带检测框的可视化图，方便人工检查。

### 3.2 非目标

当前脚本不负责：

- 将大图切成 tile 后分别推理；
- 使用 OCR、OpenCV 或其他检测器辅助模型；
- 自动纠正或猜测模型输出的 JSON；
- 对重复框执行 NMS 或去重；
- 合并相邻模块；
- 对模型漏检内容进行第二次追问；
- 计算 precision、recall、IoU 等数据集级评估指标；
- 判断模型输出的模块类别是否符合某个固定 taxonomy；
- 提供 GUI 或 Web 服务。

## 4. 目标用户

- 评估本地视觉语言模型能力的研发人员；
- 比较不同 Qwen 模型、量化版本或推理服务配置的算法工程师；
- 需要审查模型原始检测行为的测试人员；
- 为后续图像模块检测方案建立 baseline 的项目成员。

## 5. 典型使用场景

### 5.1 单图能力检查

用户提供一张图片，脚本调用指定 Qwen 服务，输出结构化检测结果和可视化图片。

### 5.2 模型或配置对比

用户保持输入图和 prompt 不变，分别指定不同模型、温度或 endpoint，比较各次独立运行的输出。

### 5.3 失败分析

当模型返回非法 JSON、错误 schema 或部分非法对象时，用户可以检查保存的 prompt、原始响应和错误结果，判断失败发生在生成、解析还是对象校验阶段。

## 6. 输入

### 6.1 必需输入

- 一张本地图片的文件路径。

图片必须能被 Pillow 正常打开。脚本读取后统一转换为 RGB，再编码为 PNG data URL 发送给模型。

### 6.2 可配置参数

- `--output`：输出目录；
- `--endpoint`：OpenAI-compatible API 地址；
- `--api-key`：API key；
- `--model`：模型名称；
- `--max-tokens`：模型最大输出 token 数；
- `--temperature`：采样温度；
- `--timeout`：请求超时时间。

默认 API key 可以由环境变量 `LOCAL_VLM_API_KEY` 提供。

## 7. 模型输出协议

模型应只返回一个合法 JSON 对象：

```json
{
  "objects": [
    {
      "id": 1,
      "bbox": [100, 120, 450, 520],
      "description": "模块内容的简短描述"
    }
  ]
}
```

边界框使用 `[x_min, y_min, x_max, y_max]`，坐标范围为 `0..1000`，原点位于左上角。

## 8. 功能需求

### FR-1 输入验证

- 输入图片不存在时必须报错并终止。
- `max_tokens` 必须大于零。
- `timeout` 必须大于零。

### FR-2 单次完整图推理

- 每次运行只向模型提交一次请求。
- 请求中必须包含完整图片，不得切图。
- system prompt 和 user prompt 必须固定保存到输出目录。

### FR-3 原始响应保存

- 模型响应必须原样保存为 `raw_response.txt`。
- 清理 `<think>` 和 Markdown code fence 只用于 JSON 解析，不得修改保存的原始响应。

### FR-4 严格 JSON 解析

- 顶层值必须是 JSON object。
- 不得自动补字段、补括号或修复格式错误。
- 解析失败时必须输出 `json_parse_error` 状态。

### FR-5 对象校验

- 顶层必须包含 `objects` 数组。
- 每个对象必须是 JSON object。
- `bbox` 必须恰好包含四个数字。
- 坐标必须位于 `[0, 1000]`。
- 必须满足 `x_min < x_max` 和 `y_min < y_max`。
- `description` 必须是字符串。
- `id` 必须是非空标量；缺失时允许使用对象序号。
- 一个非法对象不得导致其他合法对象被丢弃。

### FR-6 坐标转换

- 合法的归一化坐标必须按原图宽高转换为像素坐标。
- 坐标转换只能进行比例换算和取整，不得调整、合并或过滤合法框。

### FR-7 结果可视化

- 只绘制通过校验的检测框。
- 每个框需要显示对应 ID。
- 不得改变检测框几何形状。

### FR-8 可审计输出

每次运行应生成：

- `system_prompt.txt`；
- `user_prompt.txt`；
- `run_config.json`；
- `raw_response.txt`；
- `parsed_response.json`，仅在 JSON 解析成功时生成；
- `results.json`；
- `visualization.png`，仅在顶层 schema 可处理时生成。

## 9. 状态与退出码

| 状态 | 含义 | 退出码 |
|---|---|---:|
| `ok` | 所有对象均通过校验 | `0` |
| 顶层运行异常 | 文件、网络、API 或其他未分类异常 | `1` |
| `json_parse_error` | 模型输出不是可解析的 JSON object | `2` |
| `schema_error` | 顶层缺少合法的 `objects` 数组 | `3` |
| `partial_schema_error` | 至少一个对象合法，同时存在非法对象 | `4` |

## 10. 成功标准

一次工具运行在满足以下条件时视为技术执行成功：

1. 完整原图被准确提交给指定模型一次；
2. 原始响应和运行参数得到保存；
3. 合法对象被无损转换为像素坐标；
4. 非法对象被记录且不会污染合法对象；
5. `results.json` 的状态和进程退出码一致；
6. 可视化只反映模型通过校验的原始检测结果。

模型检测质量本身需要通过人工检查或未来的数据集评估工具衡量，不等同于脚本技术执行成功。

## 11. 约束与风险

- 模型必须支持 OpenAI-compatible Chat Completions 和图像输入。
- 完整大图可能超过服务端图像或上下文限制。
- 视觉模型可能输出 Markdown、思考标签或非法 JSON。
- 单次盲测不提供统计显著性；模型对相同输入也可能因推理后端而产生差异。
- 当前项目未锁定 Python 包版本，不同 SDK 或 Pillow 版本可能导致兼容性差异。
