# Qwen 图像模块盲测工具 PRD

## 1. 产品概述

`qwen_module_blind_test.py` 是一个面向视觉模型评估的命令行工具。它将一张完整原图一次性提交给兼容 OpenAI API 的 Qwen 视觉语言模型，让模型直接识别图像中在视觉结构或语义上相对独立的内容模块，并输出每个模块的边界框和简短描述。

该工具的核心目的不是获得经过工程优化的最佳检测结果，而是建立一个受控、可复现的盲测基准，用来观察模型在没有传统视觉预处理和检测后处理帮助时的原生模块发现与定位能力。

## 2. 背景与问题

复杂图像可能包含多个相对独立的内容区域，例如工程图视图、注释区域、表格、标题栏或其他结构化模块。在完整检测系统中，切图、OCR、OpenCV 候选生成、NMS、框合并和多次模型请求都会影响最终结果，因此难以判断结果究竟来自模型自身能力，还是来自外围工程策略。

本工具通过固定以下条件隔离模型能力：

- 使用未经切片的完整图像；
- 只进行一次模型请求；
- 不使用 OCR 或传统视觉算法生成候选；
- 不做 NMS、边界框合并或语义补全；
- 不修复模型生成的非法 JSON；
- 只对合法结果做 schema 校验和坐标换算。

## 3. 产品目标

### 3.1 核心目标

1. 测量 Qwen VLM 对完整图像中独立内容模块的零样本发现能力。
2. 测量模型输出归一化边界框的定位能力。
3. 保存足够的原始数据，使单次测试结果可以审计和复查。
4. 严格区分模型原始输出、解析结果、有效检测和无效对象。
5. 生成带检测框的可视化图，方便人工检查。

### 3.2 非目标

当前脚本不负责：

- 将大图切成 tile 后分别推理；
- 使用 OCR、OpenCV 或其他检测器辅助模型；
- 自动纠正或猜测模型输出的 JSON；
- 对重复框执行 NMS 或去重；
- 合并相邻模块；
- 对模型漏检内容进行第二次追问；
- 计算 precision、recall、IoU 等数据集级评估指标；
- 判断模型输出的模块类别是否符合某个固定 taxonomy；
- 提供 GUI 或 Web 服务。

## 4. 目标用户

- 评估本地视觉语言模型能力的研发人员；
- 比较不同 Qwen 模型、量化版本或推理服务配置的算法工程师；
- 需要审查模型原始检测行为的测试人员；
- 为后续图像模块检测方案建立 baseline 的项目成员。

## 5. 典型使用场景

### 5.1 单图能力检查

用户提供一张图片，脚本调用指定 Qwen 服务，输出结构化检测结果和可视化图片。

### 5.2 模型或配置对比

用户保持输入图和 prompt 不变，分别指定不同模型、温度或 endpoint，比较各次独立运行的输出。

### 5.3 失败分析

当模型返回非法 JSON、错误 schema 或部分非法对象时，用户可以检查保存的 prompt、原始响应和错误结果，判断失败发生在生成、解析还是对象校验阶段。

## 6. 输入

### 6.1 必需输入

- 一张本地图片的文件路径。

图片必须能被 Pillow 正常打开。脚本读取后统一转换为 RGB，再编码为 PNG data URL 发送给模型。

### 6.2 可配置参数

- `--output`：输出目录；
- `--endpoint`：OpenAI-compatible API 地址；
- `--api-key`：API key；
- `--model`：模型名称；
- `--max-tokens`：模型最大输出 token 数；
- `--temperature`：采样温度；
- `--timeout`：请求超时时间。

默认 API key 可以由环境变量 `LOCAL_VLM_API_KEY` 提供。

## 7. 模型输出协议

模型应只返回一个合法 JSON 对象：

```json
{
  "objects": [
    {
      "id": 1,
      "bbox": [100, 120, 450, 520],
      "description": "模块内容的简短描述"
    }
  ]
}
```

边界框使用 `[x_min, y_min, x_max, y_max]`，坐标范围为 `0..1000`，原点位于左上角。

## 8. 功能需求

### FR-1 输入验证

- 输入图片不存在时必须报错并终止。
- `max_tokens` 必须大于零。
- `timeout` 必须大于零。

### FR-2 单次完整图推理

- 每次运行只向模型提交一次请求。
- 请求中必须包含完整图片，不得切图。
- system prompt 和 user prompt 必须固定保存到输出目录。

### FR-3 原始响应保存

- 模型响应必须原样保存为 `raw_response.txt`。
- 清理 `<think>` 和 Markdown code fence 只用于 JSON 解析，不得修改保存的原始响应。

### FR-4 严格 JSON 解析

- 顶层值必须是 JSON object。
- 不得自动补字段、补括号或修复格式错误。
- 解析失败时必须输出 `json_parse_error` 状态。

### FR-5 对象校验

- 顶层必须包含 `objects` 数组。
- 每个对象必须是 JSON object。
- `bbox` 必须恰好包含四个数字。
- 坐标必须位于 `[0, 1000]`。
- 必须满足 `x_min < x_max` 和 `y_min < y_max`。
- `description` 必须是字符串。
- `id` 必须是非空标量；缺失时允许使用对象序号。
- 一个非法对象不得导致其他合法对象被丢弃。

### FR-6 坐标转换

- 合法的归一化坐标必须按原图宽高转换为像素坐标。
- 坐标转换只能进行比例换算和取整，不得调整、合并或过滤合法框。

### FR-7 结果可视化

- 只绘制通过校验的检测框。
- 每个框需要显示对应 ID。
- 不得改变检测框几何形状。

### FR-8 可审计输出

每次运行应生成：

- `system_prompt.txt`；
- `user_prompt.txt`；
- `run_config.json`；
- `raw_response.txt`；
- `parsed_response.json`，仅在 JSON 解析成功时生成；
- `results.json`；
- `visualization.png`，仅在顶层 schema 可处理时生成。

## 9. 状态与退出码

| 状态 | 含义 | 退出码 |
|---|---|---:|
| `ok` | 所有对象均通过校验 | `0` |
| 顶层运行异常 | 文件、网络、API 或其他未分类异常 | `1` |
| `json_parse_error` | 模型输出不是可解析的 JSON object | `2` |
| `schema_error` | 顶层缺少合法的 `objects` 数组 | `3` |
| `partial_schema_error` | 至少一个对象合法，同时存在非法对象 | `4` |

## 10. 成功标准

一次工具运行在满足以下条件时视为技术执行成功：

1. 完整原图被准确提交给指定模型一次；
2. 原始响应和运行参数得到保存；
3. 合法对象被无损转换为像素坐标；
4. 非法对象被记录且不会污染合法对象；
5. `results.json` 的状态和进程退出码一致；
6. 可视化只反映模型通过校验的原始检测结果。

模型检测质量本身需要通过人工检查或未来的数据集评估工具衡量，不等同于脚本技术执行成功。

## 11. 约束与风险

- 模型必须支持 OpenAI-compatible Chat Completions 和图像输入。
- 完整大图可能超过服务端图像或上下文限制。
- 视觉模型可能输出 Markdown、思考标签或非法 JSON。
- 单次盲测不提供统计显著性；模型对相同输入也可能因推理后端而产生差异。
- 当前项目未锁定 Python 包版本，不同 SDK 或 Pillow 版本可能导致兼容性差异。



# Claw View PDF 扫描工作台需求补充

## 工作台目标

扫描工作台需让用户在核验结果表中直接修正识别字段、导出可交付的 Excel 检验表，并能在同一屏幕内独立浏览结果表和 PDF 图纸。

## 新增功能需求

### CV-FR-1 检验表字段编辑

- 左侧检验表支持直接编辑 Project、Revision、Author、Date、Module、Page、FAI、SPC、Description、Nominal、USL、LSL、100%、DC、Points 等数据列。
- 每项修改通过后端接口持久化到当前扫描任务；刷新后显示保存值。
- `No.` 为顺序编号，不提供编辑；SPC 截图由现有框选/重截功能维护。
- 保存失败时保留用户编辑内容并显示错误反馈，允许重试。

### CV-FR-2 Excel 导出

- 左侧表格下方提供 Excel 导出入口，导出当前扫描任务的检验记录。
- 导出列顺序为：No.、Project、Revision、Author、Date、Module、Page、FAI、SPC、Description、Nominal、USL、LSL、100%、DC、Points、SPC截图。
- 前四项图纸资料作为每条记录的四列；保留 `No.` 列作为第一列。
- SPC截图列嵌入该记录当前有效截图（人工重截优先于模型截图）；无截图时留空。
- 导出表头、列宽、边框和蓝色表头风格参考 Excel Format 示例图。

### CV-FR-3 面板宽度与表格布局

- 中间分隔线向左拖动时压缩左侧表格、扩大右侧图纸；向右拖动时相反。
- 左侧表格不出现横向滚动条；列应在面板宽度内压缩或换行显示。
- `No.` 列保持可见，表格表头随左侧面板垂直滚动保持置顶。

### CV-FR-4 隐藏式纵向滚动条

- 左侧表格和右侧图纸区域各自拥有独立的垂直滚动。
- 滚动条默认隐藏，在鼠标靠近中间分隔线时显示；离开该交互区域后隐藏。
- 使用鼠标滚轮时只滚动鼠标所在面板，左右面板互不带动。

## 成功标准

1. 编辑任一可编辑字段后刷新页面，修改仍存在。
2. 导出的 xlsx 列顺序与参考图一致，包含 No.，并将有效 SPC 截图嵌入对应行。
3. 调整分隔线不会产生左侧横向滚动条，表格内容在窄宽度下仍可读。
4. 左右面板可独立垂直滚动，分隔线附近可唤出各自的隐藏滚动条。

# 精修框选择与局部放大需求补充

## 功能需求

### CV-FR-5 页面精修框筛选与单框编辑

- 大图和部件图仅绘制已经生成并写入检验记录的 `crop_refined` 精修框；不得展示尚未精修的 Stage 1 模块框或 Stage 2 候选框。
- 所有精修框可用普通描边区分；任意时刻只允许一个框处于黄色虚线编辑态。
- 点击精修框后选中该记录并显示可拖动、可缩放的黄色虚线框；保存继续更新该记录的有效 bbox 和截图。

### CV-FR-6 选中框局部放大

- 精修框右上角提供放大镜按钮；大图视图和部件图视图行为一致。
- 点击后在当前图纸区域显示选中框及周边上下文的放大视图，不改变当前页面或记录。
- 放大视图中的框编辑仍映射至当前原图/部件图坐标，保存时继续更新同一条检验记录。
- 可从放大视图返回当前全图视图；框靠近图像边缘时，放大区域应限制在图像边界内。

### CV-FR-7 只读部件全览

- 保留现有 Stage 1 部件全览入口，继续展示整页图纸上的模块区域和模块标签。
- 部件全览是只读导航视图，不提供 Stage 1 框的拖动、缩放或截图保存。
- `crop_refined` 唯一框来源的限制适用于大图/部件编辑视图；只读部件全览保留 Stage 1 模块标注。
- 点击全览图中的任一 Stage 1 部件框，打开对应模块的部件图；模块图仅显示该模块已有的 `crop_refined` 记录框。
- 每个部件框须有清晰的 `MODULE N` 标签（例如 `MODULE 1`），标签与框的位置对应。

### CV-FR-8 大图默认保持干净

- 大图视图默认不显示任何 FAI/crop_refined 框。
- 用户点击左侧检验表的一条记录后，大图只显示该条记录对应的选中框。
- 离开该记录选择或切换页码时，不得将其他 FAI 框批量铺到大图上。

## 验收标准

1. 只有已精修并出现在检验记录中的候选框可见，未精修的 stage 框不显示。
2. 单击任一精修框后只有该框成为黄色虚线编辑框；修改后持久化并刷新截图。
3. 大图与部件图中的放大镜均可显示局部上下文；局部视图编辑后 bbox 坐标正确。
4. 返回全图不会丢失当前选中记录或未保存的视图状态。
5. “查看部件全览”能打开原有 Stage 1 总览图；其中的模块框只读，不影响精修框编辑规则。
6. 点击全览中的每个模块框都会进入相应模块图，不会只停留在全览页。
7. 大图默认无 FAI 框；点击左侧某条记录时只显示该记录的框。

# 任务恢复与后端实例生命周期

- 上传成功后，前端立即持久化 `run_id` 和创建任务时的 `backend_instance_id`。
- 页面短暂重载或 React 状态丢失时，先显示恢复状态；向同一后端实例读取该 `run_id` 并恢复结果、继续轮询，不重新上传 PDF 或创建重复任务。
- 网络暂时失败时保留当前任务画面和标识，退避重试；只有后端明确确认实例不匹配或任务已中断时才清除恢复状态。
- 后端每次进程启动生成新的 `backend_instance_id`，`/api/health` 返回该值。
- 后端启动时把数据库中上一个实例遗留的 queued/rendering/processing 任务标记为 `interrupted`；旧实例任务不得通过 API 恢复。
- 检测到实例变化后，前端清除旧任务指针和页面数据，回到新的待扫描状态。旧任务行可留在数据库供诊断，但不再作为当前任务返回。

## 验收标准

1. 任务处理中刷新或重挂载页面后恢复同一个任务，不重复上传。
2. API 暂时不可达时任务内容不消失，恢复连接后继续轮询。
3. 重启后端后实例 ID 改变，旧任务标记中断且前端回到待扫描状态。
4. 新实例拒绝旧实例 `run_id` 的任务及记录读取，不能显示旧结果。

# SPC 截图预览与右侧取景调整

- 点击左侧表格中的 SPC 截图时，右侧切到该记录所属 PDF 页并显示该记录唯一的可拖动截图框。
- 同一次点击在当前表格行正上方打开浮层，完整展示该记录当前有效的 SPC 截图；浮层底边不得越过当前行顶边，不能遮住当前行的编辑控件。上方空间较小时按比例缩小整张截图，不移到当前行下方。
- 缩略图一旦出现在表格中即可打开预览，不等待整份 PDF 扫描完成。人工调整截图框保存后，浮层与缩略图均显示新的有效截图。
- 浮层应覆盖表格而不被滚动容器裁剪；右侧拖动或缩放框时保持预览以便核对，点击左侧其他区域、按 Esc、切换任务或切换页面时关闭。
- 右侧放大镜取景显示更多框周围环境，使框相对视图稍小；默认取景范围由框宽高的 2.5 倍增至 3.0 倍，靠近页面边缘时仍保持在图像范围内。
- 右侧进入放大视图后隐藏该框的放大镜，保留返回全图和拖动/缩放截图框能力。

## 验收标准

1. 扫描进行中点击已有 SPC 缩略图，预览立即出现，右侧同时定位到对应页和选框。
2. 浮层呈现完整截图，底边始终停在当前行顶边之上；滚动或调整窗口后仍贴近当前行，不被表格容器裁剪，也不阻碍当前行编辑。
3. 人工保存新框后预览和缩略图更新；切换任务或记录不展示上一条旧截图。
4. 右侧放大视图包含比此前更多的框周边内容，框编辑坐标和保存结果保持正确，放大镜在放大后消失。
